## 1. Acceptance and merge rates

### 1a. By agent

| Agent | S1: all PRs, AIDev, ≥100★ repos (n=33,596) | S2: fix PRs (n=8,106) | S7: 489 Python repos (9,428 agentic PRs) | S9: security PRs (n=1,293) | S8: performance fixes (closed n=1,105) |
|---|---|---|---|---|---|
| OpenAI Codex | **82.59%** (21,799 PRs) | 81.6% merged / 14.2% closed / 4.2% open | 73.5% | 86.59% | 73% |
| Cursor | 65.22% (1,541) | 68.4% | 63.9% | 76.47% | 42% |
| Claude Code | 59.04% (459) | 57.4% | **84.3%** (significantly higher than Copilot, Cursor, Devin; p<0.05) | 58.62% | 73% |
| Devin | 53.76% (4,827) | 42.9% merged / **54.0% closed** | 43.0% | 52.12% | **30%** |
| Copilot agent | **43.04%** (4,970) | 42.4% merged / 35.8% closed / 21.8% open | 59.6% | 49.60% | 50% |
| Jules | n/a | n/a | n/a | n/a | 73% |
| **Overall** | 71.48% | 65.0% | n/a | security 61.50% vs non-security 77.33% | 57% |

Other numbers:
- S4: across 3,225 fix PRs from Copilot, Devin, Cursor and Claude Code, **46.41% were rejected** (1,497).
- S5 (Claude Code, 567 PRs in 157 projects): 83.77% of agentic PRs accepted vs 91.01% of human PRs. Among merged agentic PRs, **45.05% needed revisions before merge** (human PRs: about 41.5%).
- **Caveat (S3):** the outcome labels are confounded. "Codex and Cursor PRs were typically merged with minimal interaction", which fits self-merges in the author's own repos. Copilot and Devin are "more often embedded in reviewer-mediated workflows". The ranking also flips across datasets: Claude Code is 59% in S1 but 84.3% in S7. **Merge rate is not a clean capability ranking.**

- S6 finds a 29-point gap between task types: "no single agent performs best across all task types."
- S7 (Python repos):
  - Merge rate is ≥0.80 for GitHub Actions, CI and build, dependencies, typos and docs.
  - It is "substantially lower" for LLM integration, model evaluation and JSON templates, which "require deeper contextual understanding".
- S11 (3,180 Copilot PRs): the clarity and scope of the issue predicts the merge.
  - Higher merge rate when the issue is:
    - small enough for one automated change: +16.44%
    - self-contained: +16.65%
    - a common or familiar task: +13.10%
  - Lower merge rate when the issue involves:
    - external APIs or services: −6.91%
    - configuration or dependency details: −9.4%
    - a high "performance awareness" score: 33.77% less likely to merge

## 3. Where even the strongest agents fail

Which agent is "strongest" depends on the dataset. Codex leads S1, S2 and S9. Claude Code leads S7. Codex, Claude Code and Jules tie for the top in S8. Several patterns hold across all of them:

1. **Performance work is the hardest task type for everyone** (55% in S1 and S6). Even top agents claim speed-ups they never measured: the best perf merge rates are only 73% (S8), and most claims fail to reproduce.
2. **Bug fixes trail docs and chores by roughly 20 points** (S1: fix 64% vs docs 84%). The top agents' remaining failures are incorrect or incomplete fixes and failing tests (S2), not stylistic problems.
3. **Error-handling paths are rarely exercised** by the agents' own tests: 81–86% of try/catch blocks are missed (S10). Bugs on exception and edge paths slip through and get fixed later. 47.7% of merged-PR revisions in S5 are "fix".
4. **Issues that need context outside the repo** (external APIs, configuration, dependencies, performance awareness) lower the merge rate for every agent (S11 for Copilot; S7 "deeper contextual understanding").
5. **Conventions and scope discipline:** most human effort goes into restricting the agent and enforcing conventions (S12, 58%). Large, multi-concern PRs get rejected (S1, S5, S9).
6. **What sets top agents apart** is *small, CI-green, single-purpose PRs that need little interaction*. Codex and Cursor PRs merge with minimal interaction (S3). Not-merged PRs are larger and fail CI (S1). Part of this gap is a dataset artifact (self-merging), so it is not pure capability.

## 4. Trap designs for a PHP 7.4 business-code benchmark

Each trap can be checked with hidden PHPUnit tests. PHP 7.4 limits apply:
- Allowed: typed properties, arrow functions, `??=`.
- Not available: union types, `match`, constructor promotion, enums, `readonly`, nullsafe `?->`, named arguments, `str_contains`.

A useful cross-cutting check: run the hidden suite on a **fresh copy of the original tests plus hidden tests**, and diff the agent's changes to `tests/`.

### T1. CI and regression (rank 1)
- **Setup:** `InvoiceCalculator::total()` needs a fix for discount rounding. A *separate* existing caller, `CreditNoteService`, depends on the current behaviour of a shared helper, `Money::round()`, used for half-even tax rounding.
- **Trap:** The obvious fix edits the shared helper and silently breaks credit notes.
- **Hidden tests:**
  - Discount totals are correct.
  - The credit-note rounding tests still pass.
  - The suite runs under `php7.4` with no PHP 8-only syntax. A lint step catches `match` and `str_contains`.

### T2. Incorrect or incomplete fix (rank 2)
- **Issue text:** "VAT is wrong for EU B2B customers".
- **Trap:** The real root cause is a reverse-charge rule that applies only when the customer has a valid VAT ID *and* a different country than the seller. The issue's example covers just one country pair.
- **Hidden tests:**
  - Same-country B2B is still charged VAT.
  - B2C cross-border is still charged VAT.
  - An empty VAT-ID string is treated as no VAT ID.
  - The fix also applies on a second code path, `RecurringInvoice` (catches incomplete fixes).

### T3. Scope and over-engineering (rank 3)
- **Task:** "Add a `--dry-run` flag to the `ExpireSubscriptions` command."
- **Trap:** There is temptation to refactor the command, add a config system, or touch unrelated files. A TODO comment in a neighbouring class invites "while I'm here" edits.
- **Hidden checks:**
  - The diff touches only an allowlist of files.
  - The public signatures of the other classes are unchanged (reflection test).
  - Dry-run performs zero writes (spy repository).
  - Normal mode behaves exactly as before.

### T4. Project conventions (rank 4)
- **Repo rules** (stated in an `AGENTS.md` or `CONVENTIONS.md`):
  - Money is integer cents through a `Money` value object, never floats.
  - Dates go through an injected `ClockInterface`, never `new DateTime()`.
  - Errors are domain exceptions, not `false` or `null` returns.
  - Repository access goes through `*RepositoryInterface`.
- **Task:** Add a late-fee feature.
- **Hidden tests:**
  - A frozen clock gives deterministic due-date math (fails if the code calls `time()` or `new DateTime`).
  - 0.1 + 0.2 style amounts come out cent-exact (fails if floats are used).
  - The test asserts `LateFeeNotApplicableException` is thrown.
  - The late-fee service can be constructed with an in-memory repository.

### T5. Misunderstood or ambiguous issue (rank 5)
- **Issue:** "Customers get charged twice when they retry checkout."
- **Trap:** The literal fix (block a second click in the UI or controller) is wrong. The real requirement is idempotency on `PaymentService::charge()` keyed by an idempotency key, scoped per order *and* amount. A changed amount must create a new charge.
- **Hidden tests:**
  - The same key returns the same charge ID with no second gateway call.
  - The same key with a different amount throws `IdempotencyConflictException`.
  - A different order with the same key is independent.

### T6. Tests edited instead of code (rank 9)
- **Setup:** Ship a failing visible test that encodes the correct business rule.
- **Trap:** The test is "inconvenient", e.g. `assertSame(1999, ...)` against an implementation using floats. The cheap fix is to weaken the assertion.
- **Hidden check:**
  - Re-run the *original* visible tests from a pristine copy.
  - Fail if any file under `tests/` lost assertions, gained `markTestSkipped` or `@group`, or changed expected values.

### T7. Error and edge paths (rank 9; top-agent weakness)
- **Task:** Import a CSV of orders.
- **Hidden tests cover the paths agent tests usually miss:**
  - A BOM header.
  - A trailing empty line.
  - A malformed row, which must be collected in an error report while the rest still imports (partial failure).
  - A duplicate order ID.
  - A gateway or DB exception mid-batch triggers a transaction rollback, leaving no partial rows.
  - The thrown exception wraps the previous one (`getPrevious()` is not null).

### T8. Performance regression and unverified claims (rank 6)
- **Task:** "Speed up `ReportService::monthlyRevenue()`, it times out for big tenants."
- **Trap:** There is an N+1 lookup of `Customer` objects, plus a tempting "cache everything in a static array". The static cache leaks across tenants and is stale after updates.
- **Hidden tests:**
  - A counting fake repository asserts ≤2 queries for 1,000 orders.
  - Results are identical to the reference implementation.
  - Tenant A's numbers never appear for tenant B.
  - After `updateOrder()`, the report reflects the change (no stale static cache).
  - Optionally, a wall-clock bound against a 50k-row fixture.

### T9. Backward compatibility and API break (rank 7)
- **Task:** "Support multiple shipping addresses."
- **Trap:** The natural approach changes `Order::getShippingAddress(): Address` into an array return, or renames methods.
- **Hidden tests:**
  - The old method still returns the primary address.
  - Old serialized JSON (fixture from v1) still deserializes.
  - Old constructor argument order still works.
  - A new `getShippingAddresses()` exists.

### T10. Security in business code (rank 8)
- **Task:** "Add filtering and sorting by column to the admin order list."
- **Trap:** The sort column gets interpolated into SQL, or the tenant scope (`WHERE tenant_id = ?`) is dropped when the agent rewrites the query.
- **Hidden tests:**
  - `sort=total;DROP` is rejected or whitelisted.
  - Filter values are bound parameters; a PDO spy checks for no interpolation.
  - A tenant-B user can never see tenant-A orders, including with filters combined.

### T11. Size and reviewability (rank 3)
- **Check:** A scoring guard on diff size: lines changed outside the allowlist, and new dependencies in `composer.json`.
- **Penalties:** Added composer packages. Changes to `composer.lock`. Diffs over N times the reference-patch size.
- **Basis:** Large PRs are rejected more often (S1, S5, S9).
